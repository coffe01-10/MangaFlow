# 漫画风格页与图标尺寸调整

## 本次变更

- 将用户提供图标的实际图案边界适配到约 94% 的图标视口。原图主体宽 949 / 1280，约 74%；新视口为 1010，主体约 94%，视觉尺寸增加约 27%。保留原有笔尖、底板和透明背景，未重新绘制设计。
- 保留九档 ICO：16、20、24、32、40、48、64、128、256。验证每档可见主体均达到至少 90% 宽度。Windows 可执行文件和主窗口仍引用该图标。
- 新建 `StyleWorkspace`、`StyleProductionCard`，替换旧的风格半成品控件。依据网页 `assets-section.tsx` 和 `asset-production-panel.tsx`，接入模型选择、黑白/彩色模式、项目模式记忆、名称、锁定项、待分析参考页、已保存档案及四步生产流程。
- 补齐色板对象编辑、增加/删除色板项、带版本号确认、1K 测试图提交、候选状态刷新、人工通过、正式激活与缺失条件导航。激活同时检查项目默认指针和档案 ACTIVE 状态。
- 风格参考页支持上传、拖入、选择、预览、重命名、分类和删除。档案创建要求至少一张参考页；分析未启动时保留已保存档案并提示重试。
- 定时更新保留章节氛围和未保存色板，不重建整张表单；色板修改保留开始编辑时的版本号，冲突后保留输入，支持明确放弃修改后重新读取。
- 跨项目切换替换旧页面，迟到请求不更新当前页面；重复点击不重复创建档案或测试批次。

## 验证记录

构建成功，0 错误。本次测试项目构建输出 40 警告，包含其依赖和 WPF 临时工程输出。

```powershell
dotnet build apps/desktop/native-tests/MangaFlow.Native.Tests.csproj -c Release --no-restore --nologo -v quiet -clp:ErrorsOnly
dotnet apps/desktop/native-tests/bin/Release/net8.0-windows/MangaFlow.Native.Tests.dll output/style-page-review --style
```

定向检查通过：宽窄布局、模式记忆、嵌套 profile / 色板对象结构、参考和锁定项参数、刷新保留草稿、版本冲突、激活前置条件、异步候选、重复提交、离页迟到响应、跨项目隔离、九档图标主体占比。

另行启动实际 native-host / sidecar，使用独立用户目录和 SQLite，19 次真实 HTTP 检查通过：风格参考上传、档案创建/读取、模式切换和确认状态重置、色板保存与 409 冲突、缺少已通过测试图时拒绝激活、STYLE_TEST 批次创建/列表/候选读取、队列关闭时分析进入 WAITING、重复分析拒绝、参考页重命名。宿主退出码 0，临时目录与数据库已删除。

首次真实检查发现测试误将“默认风格指针”当作“已激活”状态，已对照服务端修正测试假设后重跑；客户端原本已同时检查 ACTIVE 状态。没有修改后端来迁就测试。

边界：WPF 定向检查使用 HTTP fixture；真实 HTTP 验证单独执行。未进行真实窗口鼠标逐项验收，未调用图片供应商，未验证真实生成完成后的人工审批/激活成功，也未进行动画帧率或所有显示器 DPI 的验收。
