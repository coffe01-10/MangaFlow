## 1. 执行摘要与设计目标

在 MangaFlow 0.1.0 MVP 基线中，角色资产被割裂存储为四个独立数据实体：`Character`（基础描述）、`CharacterReference`（单张参考图关联）、`Outfit`（服装档案）以及 `Style`（全项目共享风格）。这种分散结构在实际连载漫画生产中暴露出严重痛点：

1. **角色多角度与表情资产极度匮乏**：角色通常仅绑定 1 张正面参考图。当分镜需要侧面、背面、俯仰视角或强情绪表情（惊恐、大哭、狂怒）时，生图引擎缺乏依据，频繁出现“换角度就变脸、换表情就换人”的断裂现象。
2. **缺乏版本演进与不可变锁定**：角色外貌描述与参考图随创作推进随时被直接覆盖修改，导致早期页面采纳的候选图与后期资产定义失去溯源一致性。
3. **角色与服装关系松散**：服装档案独立存在，用户无法在一个统一的视窗内查看该角色在不同章节/时段的所有合法服装形态。
4. **生产门禁对角色就绪度无结构化度量**：系统只要检测到角色存在 1 张参考图就判定生产就绪，无法拦截“缺少四视图”、“缺少核心表情”或“草稿未确认”的不合格资产流向生产。

本设计提出**角色模型包（Character Model Package）**概念，将身份锚点、四视图、核心表情库、体型比例、服装集与负面约束聚合成一等资产包。通过直观的完整度度量（Completeness Gauge）、版本差异对比器（Diff Viewer）和不可变版本锁定，确保角色在整部漫画全生命周期中保持高度一致。

## 2. 现状审计与主要摩擦点（文件:行号）

基于统一基线 `2613d978f64a2faee0282c6250501a453c13df0f`，现有前端实现存在以下具体缺陷：

### 2.1 资产中心四大视图割裂
- **`apps/web/components/project-workspace/assets-section.tsx:143-211`**：
  人物设定（`characters`）、服装档案（`outfits`）、漫画风格（`style`）、原始素材（`references`）被设计为四个互不相通的 Tab 视图。用户配置一个角色的完整外观需要来回在 4 个 Tab 之间跳转。

### 2.2 角色参考图缺乏多维度矩阵
- **`apps/web/components/project-workspace/assets-section.tsx:189-198`**：
  角色的参考图绑定仅支持扁平的单张列表，没有区分“正面”、“侧面”、“背面”、“3/4视角”以及“表情参考”。用户无法直观看出角色缺少哪个关键视角的参考。

### 2.3 概念图生成未与版本固化
- **`apps/web/components/asset-production-panel.tsx:178-200`**：
  角色概念图生成工具（`CharacterConceptPanel`）在生成草稿后仅作为普通素材保存，未提供“一键打包发布为 V1.0 规范包”的工作流，导致生成的参考图容易丢失版本归属。

### 2.4 生产门禁缺乏完整度度量
- **`apps/web/components/production-readiness.tsx:90-101`**：
  生产就绪检查中，判定角色就绪的条件仅仅是 `references.length > 0`。只要用户上传了任意一张缩略图，系统就会放行，无法向用户预警多角度缺失风险。

### 2.5 分镜与页面生成无法锁定角色包版本
- **`apps/web/components/storyboard-editor.tsx:261`** 与 **`generate-section.tsx:120-138`**：
  分镜与单页生成工作台仅标记角色出镜（`VISIBLE`），无法指定使用“角色包 V1.0”还是“角色包 V2.0（破损状态）”，导致同一角色的历史生成缺乏版本隔离。

## 3. 角色模型包目标信息架构

设置统一的角色模型包工作区，整合于 `/projects/[id]/assets/characters`。

### 3.1 资产包层级结构（Package Structure）

```text
CharacterModelPackage (角色模型包本体，如：林澈 / 艾莉卡)
  ├── 身份锚点 (Identity Anchor)：姓名、常用别名、年龄段、核心性格特征
  ├── 视觉特征规格 (Visual Spec)：发型发色、面部五官、瞳色、体型比例、标识性特征（伤疤/眼镜/胎记）
  ├── 负面约束与防崩词 (Negative Constraints)：禁止变更的发色、禁止添加的饰品等
  ├── PackageVersions (不可变模型包版本，如：V1.0 初始学生版 / V2.0 觉醒战斗版)
  │     ├── 封面图 (Cover Portrait)
  │     ├── 完整度指数 (Completeness Score: 0~100%)
  │     ├── 四视图矩阵 (Multi-View Matrix)：正面 (Front)、侧面 (Side)、背面 (Back)、3/4 侧面
  │     ├── 表情矩阵 (Expression Matrix)：自然 (Neutral)、喜悦 (Joy)、愤怒 (Anger)、悲伤 (Sorrow)、惊恐 (Shock)
  │     ├── 姿态库 (Pose Library)：站姿、战斗姿态、施法/奔跑
  │     └── 绑定服装集 (Assigned Outfits)：校服 (默认)、常服、作战服
  └── 生产状态 (Status)：草稿 (DRAFT) / 已确认 (READY) / 生产中 (IN_PRODUCTION) / 已归档 (ARCHIVED)
```

### 3.2 完整度评分度量标准（Completeness Gauge）

模型包界面顶部提供可视化的完整度计量表（满分 100 分）：
- **基础外貌与负面约束**：20 分（必填名称、发型发色、体型与禁止项）
- **多视图矩阵**：40 分（正面 15分 + 侧面 10分 + 背面 10分 + 3/4侧 5分）
- **核心表情集**：20 分（自然 5分 + 喜悦 5分 + 愤怒 5分 + 悲伤/惊恐 5分）
- **已绑定服装**：20 分（至少绑定 1 套已确认的服装档案）

> **门禁硬规则**：
> - 完整度 < 60% 时，角色包状态强制为 `DRAFT`（草稿），生产门禁拦截并标红报错；
> - 完整度 ≥ 60% 且人工核对通过后，方可点击【发布为已确认版本】（`READY`）；
> - 已有页面采纳该版本后，状态变为 `IN_PRODUCTION`，自动冻结编辑，修改必须【派生新版本】（如 V1.1）。

## 4. 完整用户操作流

### 4.1 创建角色包与设定身份锚点
1. 进入角色资产工作区，点击【新建角色模型包】；
2. 填写角色核心身份锚点（姓名、身份、身材比例、发型发色、常驻配饰）；
3. 设定系统级负面提示约束（如“禁止变色瞳孔、禁止改变短发设定”）；
4. 初始版本为 `V1.0 (DRAFT)`，完整度为 20%。

### 4.2 生成或上传四视图与表情矩阵
- **多角度画廊填充**：
  - 点击“正面”卡片上传已有立绘，或点击【AI 生成正面概念图】；
  - 确立正面后，点击【基于正面生成侧面与背面】，系统自动利用多模态上下文补全侧面与背面视角；
  - 表情矩阵支持一键发起“表情连拍生成”，生成 5 种标准表情微调候选。
- 填充完成后，完整度达到 80%。

### 4.3 关联服装档案
1. 在模型包详情的“专属服装集”区域，点击【添加服装】；
2. 可直接选择已有服装档案（如“青藤高校夏季校服”），或现场新建服装；
3. 将某套服装设为当前版本的“默认服装”；
4. 完整度达到 100%。

### 4.4 冻结并发布版本（Lock & Publish）
1. 用户点击【发布当前版本 V1.0】；
2. 弹出发布确认框，提示：“发布后 V1.0 将固化为不可变版本，用于后续分镜与生图。确认发布？”
3. 状态变为 `READY`。

### 4.5 分镜与页面生成绑定
1. 在分镜编辑器（`storyboard-editor`）的角色调度列表中，系统自动列出当前项目已发布的角色模型包；
2. 用户选择出镜角色，并可明确指定版本（默认为最新稳定版 V1.0）；
3. 单页生成时，生图引擎将该版本的四视图、当前分镜要求的表情与服装参考图打包发送给渲染流水线。

### 4.6 派生新版本与差异对比（Fork Version & Diff）
1. 当剧情发展角色发生重大变化（如剪短发、获得新战斗武装）时，点击【派生新版本】（创建 `V2.0 Draft`）；
2. 修改对应发型描述与新四视图；
3. 点击【版本差异对比】（Diff Viewer），界面左右并排展示 V1.0 与 V2.0 的特征差异与参考图更迭；
4. 确认后发布 V2.0，已生成的 V1.0 历史页面不受影响。

## 7. 可访问性、键盘与焦点

1. **矩阵画廊键盘导航**：
   - 四视图矩阵与表情画廊支持方向键（`ArrowLeft`/`ArrowRight`/`ArrowUp`/`ArrowDown`）无缝切换焦点；
   - 空卡片在获得焦点时，按 `Space` 或 `Enter` 键直接打开上传/生成弹层。
2. **读屏器（Screen Reader）支持**：
   - 完整度计量条使用 `role="progressbar"`，并带有 `aria-valuenow="{score}"`、`aria-valuemin="0"`、`aria-valuemax="100"` 与 `aria-label="角色包完整度"`；
   - 参考图卡片统一使用语义化 `alt`（如 `林澈 V1.0 - 侧面参考图`）。
3. **模态弹层与差异对比**：
   - 版本对比窗口内置 Focus Trap，并支持 `Esc` 键一键退出。

## 8. 对 V02-22 数据契约的依赖（只读声明）

本前端设计依赖以下由后端 L3 任务（`V02-22`）交付的数据结构与接口，本设计不越权决定数据库底层字段：

1. **`CharacterModelPackage` 模型**：包含 `id`、`project_id`、`name`、`aliases`、`identity_spec`、`negative_constraints`、`current_version_id`、`status`。

3. **版本差异比对接口**：
   - `GET /api/v1/projects/{id}/characters/{pkg_id}/diff?base={v1}&target={v2}`
4. **批量表情与多角度生成接口**：
   - `POST /api/v1/projects/{id}/characters/{pkg_id}/versions/{v_id}/generate-views`
   - `POST /api/v1/projects/{id}/characters/{pkg_id}/versions/{v_id}/generate-expressions`
