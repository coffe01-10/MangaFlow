## 1. 执行摘要与设计目标

在 MangaFlow 0.1.0 MVP 基线中，漫画场景（地点、建筑、环境）并未作为独立资产进行管理，而是作为纯文本字符串分散于剧本场景（`ScriptScene.location`）和分镜格子（`StoryboardPanel.background`）中。这导致了以下严重的生产摩擦点：

1. **场景无法保持视觉连续性**：由于没有统一的场景资产和参考图，同一地点在不同页面和格子中生图时，建筑结构、门窗方位、空间比例频繁发生漂移。
2. **时间与天气变体缺乏结构化表达**：同一地点在“清晨/黄昏/深夜”或“晴天/雨雪”下的光影与色调无法通过资产复用，用户每次都必须在分镜提示词中手动重复描述。
3. **资产管理与剧本/分镜脱节**：参考资产区仅有人物、服装和风格档案，用户上传的环境背景图只能堆积在“原始素材”中，无法与具体剧本分场关联。
4. **生成生产门禁未覆盖场景**：单页生成与整章导出仅校验了人物与服装参考，缺少对场景参考图有效性的检查机制。

本设计旨在将场景升级为**一等视觉资产（First-class Visual Asset）**，构建包含“基础地点档案 + 环境变量 + 多角度参考图 + 剧本/分镜双向绑定”的场景资产工作区（Scene Asset Workspace），并给出完整的 UI 信息架构、文字线框、状态机与测试矩阵。

## 2. 现状审计与主要摩擦点（文件:行号）

基于统一基线 `2613d978f64a2faee0282c6250501a453c13df0f`，现有前端实现存在以下具体缺陷：

### 2.1 资产中心缺少场景入口
- **`apps/web/components/project-workspace/assets-section.tsx:143-161`**：
  子导航标签写死为 `characters`（人物设定）、`outfits`（服装档案）、`style`（漫画风格）、`references`（原始素材），完全缺少 `scenes`（场景资产）工作区入口。
- **`apps/web/components/project-workspace/labels.ts:25-35`**：
  资产用途字典仅包含 `CHARACTER_REFERENCE`、`OUTFIT_REFERENCE`、`STYLE_REFERENCE`，无 `SCENE_REFERENCE` 分类。

### 2.2 剧本场景为自由纯文本
- **`apps/web/components/script-editor.tsx:110-116`**：
  剧本场景编辑弹窗中，`location`（地点）、`time_label`（时间）、`weather`（天气/氛围）全为孤立的文本输入框（`<input>`）。用户输入“学校天台”后，无法关联系统内已有的天台资产，每次新建场景都需要重新手打。
- **`apps/web/components/script-editor.tsx:118-127`**：
  剧本编辑区仅有“本场服装指定”（`scene.outfit_assignments`），没有“本场场景资产指定”（`scene.scene_asset_id`）。

### 2.3 分镜格子背景缺少参考图关联
- **`apps/web/components/storyboard-editor.tsx:258`**：
  分镜编辑抽屉中，`background`（背景）仅为一个自由的 `<textarea>`，只能由模型自行脑补绘制，无法向生图引擎提供地点主参考图与空间角度参考。
- **`apps/web/components/storyboard-editor.tsx:269`**：
  分镜信息只展示景别、角度、动作、道具，无法感知当前格子所处的场景版本。

### 2.4 生产准备与生成继承遗漏场景
- **`apps/web/components/production-readiness.tsx:90-108`**：
  生产就绪检查仅核对人物出镜（`VISIBLE`）和服装绑定，对场景道具（`props`）和背景地点未进行资产有效性检验。
- **`apps/web/components/project-workspace/generate-section.tsx:120-138`**：
  生成工作台的 `CAST & REFERENCES` 区域仅展示和继承人物及服装图，场景参考图被完全丢弃，导致生图 Prompt 缺少场景一致性约束。

## 3. 场景资产目标信息架构

设置专用的场景资产工作区，位于 `/projects/[id]/assets/scenes`。

### 3.1 资产层级结构（Hierarchy）

```text
SceneAsset (场景地点本体，如：主角家客厅 / 学校天台 / 枫树林道)
  ├── 基本信息：名称、别名、类别（室内/室外/过渡空间）、固定建筑与固定物件
  ├── 空间与画风规则：固定色彩基调、禁止变动特征（如落地窗方位、沙发颜色）
  ├── 默认主参考图 (Canonical Reference Image)：确立核心空间透视与结构
  └── SceneVariants (场景环境变量变体，如：客厅-黄昏暖光 / 天台-暴雨 / 枫树林-冬雪)
        ├── 环境变量：时间 (Time)、天气 (Weather)、光照 (Lighting)、季节 (Season)
        ├── 变体覆盖规则：光影色板微调、环境特效提示词
        └── 变体专属参考图 / 概念图 (Variant Reference Images)
```

### 3.2 资产状态流转

| 状态 | 标识 | 说明 | UI 表现 |
| --- | --- | --- | --- |
| **待确认** | `NEEDS_CONFIRMATION` | 新创建、未绑定有效参考图或未通过人工确认 | 黄色徽标；是否阻断按既有 production readiness 规则决定 |
| **规范参考** | `CANONICAL` | 至少拥有 1 张规范参考图，并通过人工确认 | 绿色徽标，可绑定到 Scene 并用于正式生图 |
| **使用中** | 派生状态，不持久化为 `IN_USE` | 正在被 Scene 或生产任务引用 | 蓝色锁形指示；由引用计数/租约派生，不与 AssetStatus 生命周期互斥 |
| **已归档** | `ARCHIVED` | 软删除状态，从主列表隐藏 | 移入历史回收站，可一键恢复 |

## 4. 完整用户操作流

### 4.1 创建场景资产与基础设定
1. 进入 `/projects/[id]/assets/scenes`，点击【新建场景】。
2. 填写场景名称（如“林间木屋”）、空间类型（室内/室外）、简要空间结构与固定物件（如“壁炉在正北墙面、木质双层书架”）。
3. 保存后生成基础场景卡片（状态为 `NEEDS_CONFIRMATION`）。

### 4.2 上传或生成场景参考图
- **手动上传**：将已有的概念图、3D 渲染图或实景参考图拖入上传区，系统自动完成尺寸/格式校验并保存为素材。
- **AI 概念图生成**：
  1. 选择当前启用的图片模型；
  2. 根据场景描述自动生成 1K 场景概念草图；
  3. 用户在生成的候选图中对比、放大查看；
  4. 点击【确认为规范参考图】，场景状态转为 `CANONICAL`。

### 4.3 建立环境变体（Time & Weather Variants）
1. 在场景详情中点击【添加环境变体】；
2. 选择时间（清晨/正午/黄昏/夜间）、天气（晴朗/阴雨/暴雪/大雾）及光照（逆光/室内暖光/冷阴影）；
3. 系统自动组合为变体名称（如“林间木屋 · 暴风雪深夜”）；
4. 上传或生成该变体的专项参考图，并保存为该变体的视觉规范。

### 4.4 剧本场景绑定与智能映射
1. 在剧本编辑器（`script-editor`）中，打开场景调度单；
2. 地点输入框支持“从场景资产库选择”下拉菜单，选择“林间木屋”；
3. 时间与天气自动列出该场景已有的变体选项（如自动匹配“黄昏暖光”）；
4. 剧本场景锁定绑定的 `scene_asset_id` 与 `variant_id`。

### 4.5 分镜与页面生成自动继承
1. 分镜编辑器自动从所属剧本场景继承绑定的地点与变体，格子中可按需微调视线角度（平视/俯拍/特写）；
2. 进入单页生成（`generate-section`）时，`CAST & REFERENCES` 面板自动显示当前页所处场景的参考图缩略图；
3. 生图引擎将场景主参考图与人物/服装参考图一同组装为上下文多模态输入，确保空间与角色双重一致。

### 4.6 软删除与引用保护
1. 点击删除场景时，系统检测引用状态；
2. 若当前场景被任何剧本场景或分镜格子绑定，弹出警示：“该场景正在被第 1、3 场剧本使用，删除将导致关联分镜失去场景参考。确认归档？”
3. 确认后移入归档区，保留历史候选生成记录中的溯源指针。

## 7. 可访问性、键盘与焦点

1. **Tab 导航与焦点管理**：
   - 场景列表支持键盘 `Up`/`Down` 导航选择；
   - 切换场景卡片时，焦点平滑移入主详情面板标题（`SceneDetailHeader`）；
   - 模态弹窗（如添加变体、删除确认）内置 Focus Trap，`Esc` 键快捷关闭并回焦到触发按钮。
2. **图片替代文本（Alt Text）**：
   - 场景主参考图必须具有格式化 `alt`：`【场景名称】主空间参考图`（例如 `学校天台 主空间参考图 - 俯拍`）；
   - 变体图 `alt`：`【场景名称】环境变体 - 【变体名称】`。
3. **读屏语义与 ARIA 属性**：
   - 变体画廊使用 `role="region"` 并设置 `aria-label="环境变体列表"`；
   - 场景选择器使用 `aria-expanded` 与 `aria-controls` 关联下拉弹层。

## 8. 对 V02-20 数据契约的依赖（只读声明）

本前端设计依赖以下由后端 L3 任务（`V02-20`）交付的数据结构与接口，本设计不越权决定数据库底层字段：

1. **`SceneAsset` 模型**：严格采用 V02-20 的 `id/project_id/name/description/structured/status/version/deleted_at`；地点分类、固定特征等进入受版本约束的 `structured`，不得另造同义顶级字段；规范参考通过关系表 role 表达。
2. **`SceneAssetVariant` 模型**：严格采用 V02-20 的 `scene_asset_id/name/structured_overrides/version/deleted_at`；参考图通过 `SceneAssetVariantReference` 关系表表达，不使用 JSON ID。
3. **剧本与分镜关联外键**：
   - `ScriptScene` 支持可选的 `scene_asset_id` 与 `variant_id`；
   - 首发只在 `Scene` 上绑定 `scene_asset_id/scene_asset_variant_id`；Panel 继续通过 `page.scene_ids` 间接消费。格级覆盖必须另立契约，不能在 UI 文档中先造字段。
4. **场景概念图生成接口**：
   - `POST /api/v1/projects/{id}/scenes/{scene_id}/generate-concept`
   - `POST /api/v1/projects/{id}/scenes/{scene_id}/variants/{variant_id}/generate-test`
