## 1. 执行摘要与设计目标

在 MangaFlow 0.1.0 MVP 基线中，AI 模型调用的 Token 消耗与计费数据仅以极简估算值零散附着在任务记录（`Job.metrics.estimated_cost`）中。用户与创作者面临以下核心痛点：

1. **成本黑盒与缺乏汇总**：系统设置与首页中完全没有全站或多项目的用量统计看板，创作者无法获知当月总花费、各供应商（OpenAI / Anthropic / Vertex / 网关）消耗占比及异常激增原因。
2. **虚假精确度与状态混淆**：供应商返回 usage 只代表数量为 reported，按本地价格表计算的金额仍是 estimated；只有运营对账导入才是 billed。CLI 通道成本默认 unknown/not applicable，不能推断为免费。
3. **无法下钻追溯（No Drill-down）**：当某批次生成费用异常偏高时，用户无法从汇总卡片下钻到具体的工作流节点、单页生成记录（`GenerationRecord`）乃至底层单次重试尝试（`ModelCallAttempt`）。
4. **缺少时间与多维筛选**：无法按时间周期（今日/本周/自定义）、项目维度、模型类型（文字/图片/质检）进行交叉筛选与成本审计。

本设计定义了 **Token 与成本看板（Usage & Cost Dashboard）** 的完整 UX 规范，确立了清晰的五级成本语义、多维下钻交互、桌面端文字线框图、状态机与前端测试矩阵。

## 2. 现状审计与主要摩擦点（文件:行号）

基于统一基线 `2613d978f64a2faee0282c6250501a453c13df0f`，现有前端实现存在以下具体缺陷：

### 2.1 任务中心仅有孤立的一行粗暴估算
- **`apps/web/components/project-workspace/jobs-section.tsx:77`**：
  任务列表中直接渲染 `{job.metrics?.estimated_cost ? \`≈ ¥\${job.metrics.estimated_cost.toFixed(3)} · 估算值不等于供应商账单\` : null}`。
  - 摩擦点：仅显示一个带有模糊波浪号的金额，没有展示输入 Token、输出 Token、生成图片分辨率张数或具体计价版本，用户无法验证计算依据。

### 2.2 任务数据结构缺少调用尝试与计费元数据
- **`apps/web/lib/api.ts:518-534`**：
  `Job` 类型中的 `metrics` 仅定义了可选的 `execution_time_ms`、`prompt_tokens`、`completion_tokens`、`estimated_cost`。
  - 摩擦点：缺少 `pricing_version`（计价版本）、`currency`（币种）、`billing_mode`（真实返回 vs 本地预估）、`call_attempts`（失败重试与多通道调用链），使得前端无法渲染精准的成本构成。

### 2.3 系统设置与全局控制台缺少用量统计入口
- **`apps/web/app/settings/page.tsx:108-112`**：
  系统设置页面仅包含 `SystemDiagnostics`（系统诊断）与 `StorageInfo`（存储空间），完全缺少全站/跨项目的 API 调用量与费用汇总面板。
- **`apps/web/app/page.tsx:24-35`**：
  首页 Dashboard 仅统计项目数与连接在线数，缺少“今日消耗”、“近 7 日趋势”等关键运营指标。

### 2.4 工作流工作室执行日志无成本挂载
- **`apps/web/components/workflow-studio.tsx:610-630`**：
  工作流节点运行后仅展示完成状态（`COMPLETED` / `FAILED`），未展示单个节点（如剧本生成、提示词扩写、分镜质检）消耗的 Token 数量与耗费。

## 3. 成本与用量类型语义与视觉规范

为彻底杜绝“虚假精确度”，看板必须在 UI 上对以下 5 种计量状态进行严格的视觉与文案区分：

| 状态类型 | 判定条件 | UI 展示格式 | 视觉标志 | 示例 |
| --- | --- | --- | --- | --- |
| **① 账单事实 (BILLED)** | 已导入运营对账记录 `OPERATOR_BILLED` | 按原币种显示 | 绿色实心徽标 `[账单]` | 对账周期账单，不伪装成 attempt 精确费用 |
| **② 规则估算 (ESTIMATED)** | 供应商仅返回 token 数或仅本地计算字数，按预设价格表换算 | `≈ ¥ 0.1200` | 橙色虚线框 `[预估]` (带 Tooltip 说明) | Gemini Vertex 按照字符数估算 / 1K 图像标准单价估算 |
| **③ 仅用量无单价 (USAGE_ONLY)** | 统计到了准确 Token/图数，但未配置该模型的计价规则 | `1,420 Tokens (单价未配置)` | 灰色中立徽标 `[未定价]` | 用户自建网关或未知开源模型 |
| **④ 不适用/未知 (NOT_APPLICABLE/UNKNOWN)** | Mock 明确不计费可标不适用；CLI 未提供账单时为未知 | `—` | 灰色徽标 `[不适用]` / `[成本未知]` | 不把 CLI 登录订阅或外部额度推断为免费 |
| **⑤ 未返回用量 (UNAVAILABLE)** | 供应商调用成功但未返回 usage 字段，且无法本地推算 | `— (供应商未提供)` | 黄色警示徽标 `[无用量返回]` | 部分第三方代理网关剥离了 usage 响应 |

### 3.1 货币与精度规则
1. **币种明确**：严禁无单位纯数字展示。明确标注 `CNY (¥)` 或 `USD ($)`，按原始结算币种展示，不做未经确认的汇率隐式折算。
2. **精度合理**：单次调用明细展示至小数点后 4 位（如 `¥ 0.0045`）；看板顶部汇总金额保留 2 位小数（如 `¥ 128.50`）。
3. **价格版本溯源**：在看板底部标注当前采用的计费基准版本（如 `计价规则版本：2026.08-v1 · 数据缓存于 10 分钟前`）。

## 4. 看板信息架构与下钻流程（Drill-Down Flow）

```text
Level 1: 全局用量看板 (Global Overview)
   │  ├── KPI 卡片：总消费金额 (本月/今日)、总 Token 数、总生图张数、调用成功率
   │  ├── 趋势图表：每日费用堆叠面积图 (按 Provider / 项目分类)
   │  └── 排行榜：Top 消耗项目、Top 消耗模型
   │
   └── Level 2: 多维分析视图 (Dimensional Analysis)
         ├── 按供应商与连接 (By Provider / Connection)
         ├── 按项目与章节 (By Project / Chapter)
         └── 按工作流与任务类型 (By Workflow / Operation: 剧本/生图/质检)
               │
               └── Level 3: 任务批次明细 (Job Runs Table)
                     │  └── 筛选特定 Job ID，查看总耗时、总尝试次数与聚合指标
                     │
                     └── Level 4: 单次物理调用尝试抽屉 (ModelCallAttempt Drawer)
                           ├── 上游 Request ID、实际命中 Model ID、调用通道 (Direct/Gateway/CLI)
                           ├── Token 拆分：Prompt Tokens + Completion Tokens + Cached Tokens
                           ├── 延迟瀑布：TTFT (首字延迟) + 总响应耗时
                           └── 状态与重试：HTTP 状态码、失败重试前后对比
```

## 6. 状态文案规范与交互反馈

| 状态类型 | 触发条件 | UI 展示文案 | 推荐操作 |
| --- | --- | --- | --- |
| **首次无数据** | 新项目或新部署尚未发生任何模型调用 | `暂无调用记录` · `发起剧本分析或单页生成后即可在此查看用量统计` | `【前往工作台生成】` |
| **筛选无结果** | 指定时间范围或特定模型无匹配记录 | `未找到匹配的调用记录` · `请尝试调整时间范围或清除筛选条件` | `【重置筛选】` |
| **数据加载中** | 正在拉取聚合用量统计 | `正在汇总 API 用量与成本数据…` | *(骨架屏展示)* |
| **数据部分返回** | 部分供应商响应超时，仅统计了已完成项目 | `部分数据统计中 · 已展示 8/10 个连接的用量记录` | `【刷新重试未完成项】` |
| **价格表未配置** | 使用了自定义模型 ID 且未录入定价 | `该模型未配置单价表，仅展示 Token 消耗数量` | `【配置计费规则】` |
| **离线状态** | 本地网络不可用，展示本地缓存数据 | `离线模式 · 展示最后缓存于 {time} 的统计数据` | `【连接恢复后同步】` |

## 7. 可访问性、键盘与焦点

1. **时间与筛选控件无障碍**：
   - 时间选择器使用标准 `role="combobox"` 与 `aria-label="选择用量统计时间范围"`；
   - 筛选标签切换时通过 `aria-pressed` 明确选中态。
2. **图表与数据表格双模呈现**：
   - 趋势图提供隐藏的 Accessible Data Table（`role="table"`），供屏幕朗读器逐行读取日期与花费；
   - KPI 卡片包含 `aria-describedby` 关联上周期环比增减说明。
3. **下钻抽屉键盘控制**：
   - 表格行支持 `Enter` 键展开调用明细抽屉；
   - 抽屉打开时焦点自动捕获在标题，按 `Esc` 键自动关闭并回焦。

## 8. 对 V02-15A 数据契约的依赖（只读声明）

本前端设计依赖以下由后端任务（`V02-15A`）交付的统计与明细接口，本设计不越权决定服务端数据库 schema：

1. **用量聚合统计接口**：
   - `GET /api/v1/usage/summary?from={date}&to={date}&project_id={id}&provider={name}`
   - 金额按原币种分组返回 `costs_by_currency`，不得无汇率版本地汇总成 `total_cost_cny`。
2. **调用明细分页接口**：
   - `GET /api/v1/usage/calls?cursor={cursor}&limit={m}&status={status}`
   - 返回字段与 V02-15A ledger read schema 完全一致，使用 keyset cursor；`cost_mode` 为 BILLED/ESTIMATED/UNKNOWN/NOT_APPLICABLE，不存在笼统 FREE。
3. **Trace 级别物理尝试接口**：
   - `GET /api/v1/usage/attempts/{attempt_id}`
