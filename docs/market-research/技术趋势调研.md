# 技术趋势调研:2025–2026 图像/漫画生成

> 调研时间:2026-10-05。调研方法:基于公开资料(官方文档、厂商博客、GitHub 仓库、Wikipedia)交叉核对;标注了确切来源的事实可直接引用，标注"估算/传闻/来源有限"的判断不应作为决策唯一依据。本报告面向 MangaFlow(v1.0.0-rc2，私有单用户编排型 AI 漫画工作台)评估技术趋势的影响。

## 摘要

2025–2026 年图像生成领域的决定性变化是:**"参考图驱动的编辑"取代"微调"成为角色一致性的主流路线**。以 Google Nano Banana 系列(Gemini 2.5/3.x Image)和 FLUX.1 Kontext / FLUX.2 为代表的原生多图融合模型，把"上传角色设定图 + 自然语言指令 → 保持一致地改图"变成了 API 级能力,LoRA/IP-Adapter 这类训练型方案退居开源社区的补充位置。同时:

- **开源/闭源格局分层固化**:旗舰能力(多图一致性、文字渲染、4K)集中在闭源 API(Gemini Image、FLUX.2 Pro/Max、Qwen-Image 商用版);开源侧 FLUX.2 klein(Apache 2.0)、Qwen-Image-Edit、Wan2.2(Apache 2.0 视频)提供可自托管的底线方案。
- **推理成本呈"阶梯化"而非线性下降**:同一模型家族分出 Lite/Fast/Standard/Pro 档，单张 1K 图 API 价从 $0.022(批量)到 $0.24(Pro 4K)相差 10 倍以上——价格分层本身成为产品需要建模的维度。
- **视频模型进入"图生视频 + 原生音轨"阶段**(Veo 3.1、Sora 2、Kling 3.0、Wan2.2),8–20 秒带音频片段可 API 化，为"动态漫画"提供了新导出形态,但按秒计费($0.05–0.60/秒)使成本核算比静态图更敏感。
- **多模态导演式生成成为默认交互**:图像模型普遍接受"多张参考图 + 自然语言编辑指令",这与 MangaFlow 已落地的"自然语言导演 + 结构化命令提案"路线方向一致，但模型端能力(直接改图)与编排端能力(可追溯地改业务数据)需要清晰分层。

**对 MangaFlow 头条判断**:MangaFlow 的"参考资产即规范 + prompt_snapshot 冻结 + 逐页人工采用"架构，恰好是把 2025–2026 年原生参考图编辑能力变成"可追溯生产流程"所需要的编排层——趋势没有颠覆产品定位，而是抬高了它的护城河;真正的压力在模型能力位契约需要扩展(多图输入、编辑档位、视频/音轨、按分辨率计价)。

## 分项发现

### 1. 角色一致性:从训练型适配器转向原生多图参考

**技术路线现状(三条并存，重心已移动):**

| 路线 | 代表 | 状态 |
|---|---|---|
| 训练型微调 | LoRA(SD 生态)、角色 LoRA | 仍是开源社区主流工作流;LoRA 本身即"冻结基座 + 低秩增量矩阵、可合并回基座无推理开销"(Wikipedia: LoRA) |
| 免训练适配器 | IP-Adapter、InstantID、PuLID | IP-Adapter 仓库最后一次更新在 2024-01(tencent-ailab/IP-Adapter,GitHub);InstantID 2024-01 发布、仅支持 SDXL、人脸编码器部分非商用(instantX-research/InstantID,GitHub);PuLID(NeurIPS 2024,ByteDance)已支持 SDXL + FLUX,Apache-2.0,FLUX 版可在 12–16GB 显存消费卡运行(ToTheBeginning/PuLID,GitHub) |
| 原生多图参考 | Nano Banana 系列、FLUX.1 Kontext、FLUX.2 | 见下文，成为 2025 下半年起的主流 |

**关键事件:**

- **Nano Banana(Gemini 2.5 Flash Image)2025-08-26 发布**,把"主体/角色跨修改一致性"和"多图融合"作为核心卖点，数周内带动 Gemini app 新增超 1000 万用户、超 2 亿次编辑(估算，来源:Wikipedia 引述 TechRadar 等);后续 Nano Banana Pro(Gemini 3 Pro Image,2025-11-20)提升文字渲染与世界知识,Nano Banana 2(Gemini 3.1 Flash Image,2026-02-26)提速,Nano Banana 2 Lite(2026-06-30)压低成本(Wikipedia: Gemini)。
- **FLUX.1 Kontext(2025-05)** 把"文本 + 参考图的原位编辑"做成 API 能力(Pro/Max 闭源 API;Kontext [dev] 2025-06 开放权重、非商用)(Wikipedia: Flux)。
- **FLUX.2(2025-11)** 官方宣称重点改进"image reference(多图参考)、照片真实感、排版文字、提示词理解";klein 4B/9B(2026-01)Apache 2.0 开源,dev 开放权重非商用,pro/flex/max 闭源(Wikipedia: Flux;bfl.ai)。
- **Qwen-Image-Edit(2025-08-19)** 明确演示"角色一致性保持"(吉祥物 Capybara 跨编辑保持、生成表情包),支持中英双语文本原位编辑(qwenlm.github.io)。

**含义**:对漫画场景,"character sheet 包"(多角度设定图 + 服装/表情变体)从社区 trick 变成厂商官方支持的输入形态；单图保身份的免训练方案(PuLID/InstantID)在真人向/半身像有效，但漫画角色通常需要多资产(角色 + 服装 + 风格 + 场景)绑定，这正是原生多图参考模型覆盖的场景。

### 2. 多图编辑与局部重绘:fail-closed 能力位变得更重要

- **原位编辑(in-context editing)成为标配**:FLUX.1 Kontext、Nano Banana 全系、Qwen-Image-Edit 都支持"给图 + 指令 → 局部修改",不再需要 mask/ControlNet 级别的手工条件(各来源同上)。
- **Qwen-Image-Edit 的双语文字原位编辑**(增删改图中文字且保留字体/大小/样式)对漫画对白修正有直接价值(qwenlm.github.io/blog/qwen-image-edit)。
- **能力分化明显**:文字渲染、多图输入数量上限、分辨率档位、是否支持蒙版区域编辑，各家差异很大。例:Nano Banana 系列以会话式编辑见长,FLUX.2 flex 专门强化排版，开源侧 Qwen-Image-Edit 提供可自托管基线(各来源同上)。
- **本地重绘管线**:开源生态(ComfyUI + FLUX.1 Tools Fill、SD3.5 + ControlNets)仍提供逐像素控制的 inpainting/outpainting;SD3.5(2024-10-22,8.1B Large/4 步 Turbo/2.5B Medium,社区许可证允许年收入 $1M 以下商用)(stability.ai)。

**含义**:编辑能力的"支持/不支持、支持到什么程度"在供应商间差异扩大,MangaFlow 的"区域编辑能力 fail-closed、不静默降级"策略方向正确，且需要把能力位粒度细化到:多图输入上限、蒙版编辑、文字编辑、分辨率/价格档位。

### 3. 视频与动态漫画化:API 化完成，成本按秒计

- **Veo 3.1**:原生音频(音效 + 对白)、720p–4K、图生视频("ingredients to video")、首末帧过渡、场景扩展(用末秒画面续写),API 价 $0.10–0.60/秒(按档位与分辨率分:Lite $0.05/秒起,Fast $0.10/秒起,Standard $0.40/秒起;Gemini API 定价页,2026-10 抓取)。
- **Sora 2(2025-09-30)**:一度是消费端爆款(iOS app + cameo),但版权争议巨大——默认使用受版权内容、遭日本内容海外发行协会(含吉卜力、Square Enix 成员)抗议,Disney 一度授权后又因产品关停终止;**OpenAI 2026-03-24 宣布停服,app 2026-04-26 关闭、API 2026-09-24 关停**(Wikipedia: Sora)。教训:视频模型供应商生命周期风险是真实的。
- **Kling(快手)**:2024-06 起快速迭代,2026-02-07 Kling 3.0 稳定版;在第三方榜单上曾排在 Sora 2 Pro 之上(Wikipedia: Kling AI;来源有限，具体规格未逐版核实)。
- **开源侧 Wan2.2(阿里,2025-07-28,Apache 2.0)**:T2V/I2V-A14B(480p/720p,MoE 双专家)、TI2V-5B 可在 24GB 消费卡(如 4090)跑 720p24fps、S2V 语音驱动、Animate 角色动画;已集成 ComfyUI/Diffusers(Wan-Video/Wan2.2,GitHub)。
- **Gemini Omni Flash**:多模态输入 + 会话式多轮编辑的视频生成/编辑模型,$1.50/M 输入、视频输出 $17.50/M token(约 $0.10/秒 720p)(Gemini API 定价页)。

**含义**:"动态漫画"(静态页 + 微动效/镜头推拉/对口型)的技术原料已齐备且开源可自托管，但按秒计费使单次导出成本敏感性远高于静态页;供应商突然停服(Sora 先例)要求导出层对"视频供应商"保持与图像供应商相同的平权/可替换设计。

### 4. 多模态导演式生成:自然语言成为图像模型的一等输入

- Nano Banana 系列的核心交互即"会话式多轮编辑"(Wikipedia: Gemini);Gemini Omni Flash 同样以"多轮会话编辑"为主打(Gemini API 文档)。
- FLUX.2 用 Mistral-3(24B VLM)做视觉语言理解以改善提示词遵循(Wikipedia: Flux)。
- Qwen-Image-Edit 用 Qwen2.5-VL 做视觉语义控制(qwenlm.github.io)。

**含义**:"自然语言 → 结构化编辑"在模型端已是现实;MangaFlow 的差异化不在"能听懂中文指令",而在把指令变成**schema 校验过、可预览、逐项确认、可撤销、带版本锚点与用量记录**的命令提案(docs/roadmap.md:69–94 已落地 DIR-01A/B/C)——即模型能力之上的一层治理。这条路线与趋势同向，应坚持;需要跟踪的是图像模型本身开始接受"指令 + 参考图 → 新图"后,`image_edit` 能力位要表达"文本指令编辑"与"蒙版编辑"的区别。

### 5. 开源与闭源格局(截至 2026-10)

| 阵营 | 旗舰 | 许可/接入 | 对私有单用户工具的意义 |
|---|---|---|---|
| Google | Nano Banana Pro / 2 / Lite(Gemini 3 Pro/3.1 Flash Image);Veo 3.1 | 闭源 API(Gemini API / Vertex) | 多图一致性与文字渲染标杆;Nano Banana 2.5 Flash Image 旧版已定 2026-10-02 停服，说明"预设模型会过期",模型目录须可替换 |
| BFL | FLUX.2 pro/flex/max、FLUX 3(2026-07，文生视频，闭源) | API-only;klein Apache 2.0、dev 权重非商用 | 编辑与排版强项;开源 klein 提供自托管底档 |
| OpenAI | gpt-image 系(本次未能取得官方定价页,403;价格未核实)、Sora 2 已停 | API | Sora 停服是供应商风险教科书案例 |
| Stability | SD3.5 Large/Turbo/Medium(2024-10) | 社区许可证($1M 年收入以下商用免费) | 消费卡可跑的开源底线;SDXL 生态(IP-Adapter/ControlNet/LoRA)存量最大但 2024 后适配器研究趋缓 |
| 阿里 | Qwen-Image / Qwen-Image-Edit(20B)、Wan2.2 | 开源(Qwen-Image 许可需逐仓库核实;Wan2.2 Apache 2.0) | 中文文字渲染与双语文字编辑对中文漫画最有针对性;Wan2.2 是开源动态漫画原料 |
| 字节/学术 | PuLID、InstantID、IP-Adapter | Apache 2.0 / 非商用成分混杂 | 人脸保真免训练方案;漫画角色全身/风格一致性覆盖不足 |

**含义**:供应商平权的模型平台(README.zh-CN.md:143)从"差异化卖点"变成"生存必需"——模型停服(Gemini 2.5 Flash Image 2026-10-02、Sora 2026-09-24)已是常态事件；能力位、健康检查、路由契约的抽象需要覆盖:多参考图输入、分辨率档位、视频/音轨、编辑模式(蒙版/指令)、以及按档位计价。

### 6. 推理成本:分层定价，单页成本区间拉大到 10 倍级

已从官方定价页核实的数字(2026-10-05 抓取):

- **Gemini 图像**:Nano Banana 2 系列 1K 图约 $0.045–0.067/张;Nano Banana Pro 1K/2K $0.134/张、4K $0.24/张;Lite 约 $0.034/1K;批量模式约半价(Gemini API 定价页)。
- **Veo 3.1 视频**:$0.05–0.60/秒(见第 3 节)。
- **FLUX**:官网仅见计算器入口，FLUX 3 图约 $0.024/张(768×768)起;各档位明细未能逐条核实(来源有限,bfl.ai/pricing)。
- **OpenAI 图像**:官方定价页 403 未能抓取;价格未核实。

趋势判断:同族模型按 Lite/Fast/Standard/Pro 与分辨率分层定价已成为范式;"抽卡式多候选生成"的成本不再是一个固定单价，而是"档位 × 分辨率 × 批量/优先通道"的函数。

**含义**:MangaFlow 的"逐次派发用量与成本账本"(README.zh-CN.md:158–160)方向正确且必需;建议把价格版本维度扩展到"模型档位 + 分辨率 + 批量/优先级通道",并让"生成候选"操作在派发前就能给出按档位估算的成本区间(账本已有 pending audit 机制，扩展的是价格表 schema)。

## 对 MangaFlow 的启示

按影响紧迫度排序:

1. **能力位契约扩展是最大技术债。** 现有 `image_edit` 布尔能力位(README.zh-CN.md:132)需要细化为:多参考图输入数上限、蒙版 vs 纯指令编辑、图中文字编辑、分辨率/质量档位、视频输出与音轨。趋势已证明"不支持就静默降级"不可接受(区域编辑 fail-closed 已是对的);下一步是让路由能按"本页需要的编辑模式"选模型。

2. **character sheet 包的产品形态得到官方背书。** MangaFlow 的"人物/服装/风格/场景一级资产 + 版本化角色模型包排队时冻结进 prompt_snapshot"设计，与 Nano Banana/FLUX.2/Qwen-Image-Edit 原生多图参考的输入形态天然匹配。需要验证的是:各供应商多图输入的排序语义(哪张是角色、哪张是风格)是否需要在 adapter 层做"资产类别 → 参考图槽位"的显式映射，并保持冻结语义(快照里记录槽位而不只是 URL 列表)。

3. **"抽卡"经济性改变。** 单候选成本从 ~$0.02 到 ~$0.24 差 10 倍,"多批次/跨模型候选并存"功能有了真实的成本优化空间:便宜档批量抽 + 贵档定稿，可作为路由策略建议(但自动路由必须只碰 VERIFIED 能力，现有契约保持)。

4. **动态漫画导出是低优先但有依据的候选方向。** Veo 3.1 ingredients-to-video(参考图生成视频)与 Wan2.2 Animate(角色动画，开源)使"已采用页面 → 动态片段"可行;Sora 停服案例说明该能力必须以供应商平权方式接入，且按秒计费要求用量账本支持"秒"作为计费单位(目前账本以 token/图片数为单位，见 v02-usage-ledger-contract，需核实是否已有时长维度)。

5. **自然语言导演路线被行业验证，治理层是差异点。** 模型端"听懂人话改图"普及后,MangaFlow 的价值集中在:命令提案 schema 校验、版本锚点、逐项确认/撤销、用量记录(docs/roadmap.md:69–94 已完成的部分)。值得跟踪的是图像模型直接返回"编辑后整图"与导演命令"修改业务字段"两条路径的衔接——例如把"AI 解析出的编辑"同时映射为分镜字段修改 + 触发按页重生成，而非让模型图直接绕过校对门槛(README.zh-CN.md:136 的"文字采用唯一门槛是人工校对确认"必须守住)。

6. **中文文字渲染是可争取的差异化。** Qwen-Image(-Edit)的中英双语文本渲染与图中文字原位编辑，对中文漫画对白/拟声词是直接利好；接入 Qwen 系(经 OPENAI 兼容协议或原生)可作为"文字检查"修复环节的备选供应商。

7. **不要自建一致性方案。** PuLID/InstantID/IP-Adapter 这条开源路线在 2024 后进入维护态(仓库停更),而闭源原生参考图编辑已经覆盖了它们解决的问题域;对单用户私有产品，自训练 LoRA 或部署适配器的性价比已低于"资产绑定 + 多图参考 API"。保留的能力是:如果用户配置了本地 ComfyUI/开源通道(Wan2.2、FLUX klein、SD3.5),把同样的资产绑定语义映射过去即可，不需要为本地通道额外造一致性技术。

8. **供应商生命周期纳入常态运营。** 两个 2026 年实证:Gemini 2.5 Flash Image 定 2026-10-02 停服、Sora API 2026-09-24 关停。模型目录需要"废弃(deprecated)状态 + 迁移提示",用量账本的历史记录与当前可用模型解耦——这些在现有契约框架内是增量工作，但应排进路线图。
