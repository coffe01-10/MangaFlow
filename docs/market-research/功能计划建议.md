# MangaFlow 下一迭代功能计划建议

> 起草日期:2026-10-05。输入:`市场综合分析.md`、`竞品调研.md`、`创作者需求调研.md`、`技术趋势调研.md`、`商业模式调研.md`(同目录)与产品现状摘要、`docs/roadmap.md` 在途队列。
> effort 分级参照 AGENTS.md L1/L2/L3 思想:低=仅前端/单服务;中=跨层但无迁移/事务/进程边界变更;高=涉及 schema 迁移、事务/Worker、新适配器或外部集成。
> 约束:P0 ≤ 3 条;不与 roadmap 已交付/在途项重复(分镜画布五项、PUB-01 条漫导出、DIR-01 导演、V02 全部已勾选;延迟验收清单内项不重提)。
> 「重复」的判定规则:在已交付契约上**新增能力维度**(新平台规格、新批量派发、新状态语义、新计量单位)不算重复——例如 P1-3 是 PUB-01C WEBTOON 预设的横向扩展、P2-3 是已交付单页升清的批量扩展,均视为新工作项;**重新实现已交付的同一行为**才算重复。此规则同样适用于 roadmap 自身 PRD(plan.md)中已规划但部分落地的项。
> 引用口径:源报告引用用「文件名:行号」;代码断言用 `路径:行号`(复核于 2026-10-05,行号随代码演进漂移)。

## 整体方向结论

四份调研收敛于同一判断:竞争者集体死在"一键生成",而"有治理的半自动工作流"是真空位。MangaFlow 的架构恰好压中该空位,下一迭代不应再横向扩功能面,而应**把已有的决策链、资产层、账本三条纵深优势补齐到"对外可证明、对内抗供应商风险"**:

1. **对内抗风险(生存项)**:供应商停服已发生两起实证(Gemini 2.5 Flash Image 2026-10-02、Sora API 2026-09-24),模型目录生命周期与能力位契约是必须马上补的地基,其余功能依赖其上。
2. **对外可证明(差异化)**:把"逐页人工确认+五类检查+来源关联"讲成可登记版权、可过 KDP/Steam 披露的证据链——竞品零覆盖、判例环境奖励、实现只需在现有导出层聚合已存在的数据。
3. **经济性透明(成本卖点)**:同族模型价差 10 倍创造真实优化空间,派发前估算是账本的自然延伸,直接打竞品积分制的成本盲区。

明确不做(均有跨源证据):不自建一致性技术、不做纯云订阅 SaaS、不押工具→平台分成、不做分镜体检类自动诊断(docs/roadmap.md:34-36 用户已排除)、多角色同页短期靠分镜拆分规避不立项。

## 建议清单

### P0-1 能力位契约细化:多图输入 / 编辑模式 / 文字编辑 / 分辨率档位

- **problem**:现有 `image_edit` 类布尔能力位跟不上供应商能力分化(多图输入上限、蒙版 vs 纯指令、图中文字、分辨率/价格档位各家不一),技术趋势报告指其为唯一真正的技术债;后续槽位映射、分层路由、文字编辑通道全部依赖它。
- **what**:把能力位从布尔细化为结构化声明——多参考图输入数上限、编辑模式(蒙版/指令/整图)、图中文字编辑、分辨率与质量档位(视频/音轨预留位);`GET /models` 与路由按"本页所需编辑模式"fail-closed 匹配,缺失/UNKNOWN 一律按不支持(沿用 V02-44B 语义);设置页如实展示新维度。**初值口径**:schema 落地时新维度一律以 UNKNOWN 起步,不猜值;官方文档可核实的维度(如 Gemini 图像系多图输入)由 lead 逐家填 DECLARED 并注明来源;无法核实的保持 UNKNOWN,由能力测试探针按现有 VERIFIED 机制补齐。
- **evidence**:技术趋势调研:43,:46,:77,:98(能力分化扩大、能力位粒度需细化);市场综合分析:73,:77(真正技术债只有这一处);创作者需求调研:44-48(文字编辑分化)。
- **effort**:高(跨 model_adapters、目录 schema/迁移、路由与设置页四层;属 L3 迁移面,需 lead 冻结设计)。
- **priority**:P0
- **risk**:各供应商能力声明需逐家核实,预设若错误声明会破坏 fail-closed 信任;真实供应商验证能力受"延迟验收清单"凭据约束,只能做到声明级诚实。**对依赖链的明确说明**:P1-2 槽位映射在凭据补齐前的可用面 = 仅对「多图上限有 DECLARED/VERIFIED 值」的模型生效,UNKNOWN 模型按 fail-closed 拒绝——这是契约设计意图而非缺陷,交付的是正确机制而非全线可用承诺。

### P0-2 模型目录生命周期管理(deprecated 状态 + 迁移提示 + 账本解耦)

- **problem**:供应商停服/模型退役已成常态事件,目录会把已死模型当可选,用户任务失败才发现;用量账本历史记录与当前可用模型耦合,模型下线即丢审计上下文。
- **what**:模型目录增加 lifecycle 状态(active/deprecated/eol)与 sunset 日期——本质是现有 `enabled`/`display_enabled`/`confidence` 字段(apps/api/app/models.py:1617-1621)的语义扩展:deprecated = 历史任务/账本/快照中身份可读 + 新任务不可选 + 迁移提示,eol = 附加"官方公告下线"标记。EOL 数据来源:**人工维护的 sunset 表**(JSON/实现侧常量,随版本发布更新;各供应商无统一 EOL API,自动抓公告页超出本迭代范围)。健康检查区分"下线"(sunset 表命中)与"故障"(探针失败)。
- **evidence**:技术趋势调研:70,:77,:112(Gemini 2.5 Flash Image 定 2026-10-02 停服、Sora API 2026-09-24 关停,生命周期纳入常态运营);市场综合分析:32,:57(平权从卖点升级为生存项);竞品调研:46,:53,:73(三个云端工具死亡案例)。
- **effort**:高(迁移本身小——lifecycle 是 enabled 语义扩展而非新机制;真正占工作量的是"deprecated 模型在历史重放/prompt_snapshot 复用/账本审计"的边界设计 + 路由/设置页/任务创建多处消费点改造 + sunset 表数据维护;属 L3 设计面,需 lead 冻结)。
- **priority**:P0
- **risk**:需先冻结"deprecated 模型在历史重放/prompt_snapshot 复用"的行为边界,避免一刀切禁用破坏既有候选重试;EOL 数据靠人工 sunset 表,存在滞后风险——健康检查探针失败可作兜底信号。

### P0-3 创作留痕证明包:导出内嵌制作元数据 + 平台 AI 披露模板

- **problem**:KDP/Steam 已强制 AI 内容披露、美国版权局只认"人类创造性编排",用户需要可举证的创作过程,但目前没有任何工具把留痕做成可提交物;这是竞品零覆盖且判例奖励的卖点,不产品化就只是内部架构。
- **what**:导出产物(PNG/PDF/ZIP,沿用 PUB-01C manifest 通道)内嵌可读制作元数据:每页采用记录、人工校对确认、五类检查状态、原作来源区间、prompt_snapshot 版本、模型身份(不含凭据/本地路径);新增"投稿披露包"——按 KDP/Steam 口径(已有官方条款依据,商业模式:48-49)生成 AI 使用披露声明文本,Webtoon/Tapas 等无公开专条的平台仅提供通用披露模板并明确标注"无平台背书"(商业模式:93 自注未取到专条);营销叙事同步换锚为"可证明的创作过程"。**前置条件**:README.zh-CN.md:136 注明五类检查"当前完整性校验缺口仍需人工复核"——作为对外可提交证据,须先补完整性闭环(检查项缺失时元数据如实标注"未完成"而非缺省通过),该前置工作量已计入 effort。
- **evidence**:商业模式调研:47-50,:72,:85(KDP/Steam 披露义务、人类编排可登记、导出应内嵌制作元数据);创作者需求调研:52-56(Zarya 判例、留证需求);市场综合分析:29-30,:85(四源全中、机会点排名第 1);竞品调研:112(可追溯性完全缺席)。
- **effort**:中(导出层聚合已存在的血缘/校对/检查数据 + 模板文案 + **五类检查完整性闭环的缺口补齐**——README.zh-CN.md:136 明示当前仍需人工复核,该前置工作使 effort 偏中而非低;若披露包需落库成导出记录则升一格,首版可走导出时即时生成)。
- **priority**:P0
- **risk**:元数据字段需做脱敏清单(凭据、绝对路径、内部 ID 不外泄);披露模板文案必须保持"模板"定位,不做法律效力承诺;无公开专条平台的模板文案标注"无平台背书"以避免形式主义字段。

### P1-1 派发前成本估算与分层抽卡路由建议(便宜档抽卡 + 贵档定稿)

- **problem**:抽卡成本对创作者不可见,同族模型 Lite/Pro 价差达 10 倍,但用户无法事前知道"这页候选要花多少";竞品积分制把成本藏进点数是公认盲区。
- **what**:价格表 schema 扩展"档位 × 分辨率 × 批量/优先通道"维度;任务派发前(抽卡、局部重抽卡、导演提案)给出按档位估算的成本区间;提供"便宜档批量抽卡、贵档定稿"的路由策略建议(仅建议,不自动切换模型,遵守仅碰 VERIFIED 能力的现有契约);估算与 billed 维持分开对账。**价格数据维护**:首版由 lead 从各供应商公开定价页人工抄录并标注来源与抓取日期(如 Gemini 图像 2026-10-05 抓取,技术:83-86;OpenAI 官方定价本轮未取到,标"未核实"),过期价格由用户承担误导风险——作为单用户私有产品,估算数字标注"最后更新于 X"即可,不做自动更新承诺。
- **evidence**:技术趋势调研:79-90(价差 10 倍、成本=档位×分辨率×通道函数);市场综合分析:87(机会点排名第 3);竞品调研:62,:114(积分制藏成本、账本是盲区);创作者需求调研:38-42(返工=算力费用双耗)。
- **effort**:高(价格版本 schema/迁移 + 派发路径预估算 + 前端提示位三层;价格表数据本身为人工维护的实现侧常量,无自动抓取机制)。
- **priority**:P1
- **risk**:估算不得伪装 billed/真实报价,价格数据维护需标注来源与抓取日期(OpenAI 官方定价本轮未取到,需标"未核实");单用户产品无价格更新兜底机制,过期价格由展示时间戳提示用户自行判断。

### P1-2 资产绑定 → 多图参考槽位显式映射(prompt_snapshot 记录槽位语义)

- **problem**:原生多图参考已成一致性主流输入形态,但各供应商多图排序/槽位语义不一;目前资产绑定映射为参考图列表,快照只记录"用了哪些图",不记录"哪张图担任什么角色",换模型时一致性语义漂移。
- **what**:prompt_snapshot 记录"资产类别 → 参考图槽位"显式映射(身份锚点/四视图/服装/风格/场景分别占哪个槽位),adapter 层按模型能力位(P0-1 的多图上限)裁剪与排序;把"AI 概念图 → 人工确认 → 成为规范参考"做成可演示叙事,替代社区手工维护 PNG 文件夹的现状。
- **evidence**:技术趋势调研:37,:100(character sheet 包输入形态官方背书、需 adapter 层显式映射);市场综合分析:86(机会点排名第 2);竞品调研:113(规范层无竞品实现);创作者需求调研:23,:98(中文社区手工角色卡痛点、可演示对比建议)。
- **effort**:中(adapter 映射层 + 快照契约扩展;依赖 P0-1 能力位落地后才有意义,本身无新迁移压力)。
- **priority**:P1
- **risk**:各供应商槽位语义无统一官方文档,多图排序效果差异需真实供应商实测确认——真实调用验收仍在延迟清单,落地后相关断言只能标 NOT RUN。

### P1-3 平台投稿规格包(多平台导出预设 + 随包披露模板)

- **problem**:页漫+竖条双格式发布是真实双轨需求,但各平台尺寸/切片规则不同且会持续变化;PUB-01C 已交付 WEBTOON 预设,只覆盖一家。
- **what**:把导出预设参数化为"目标平台规格包":Webtoon/Tapas/抖音条漫号等宽、切片高度、文件格式与命名规则做成可更新的实现侧常量(沿用 PUB-01B"预设不写死进数据模型"的决策);投稿 ZIP 附带 AI 披露声明文本(复用 P0-3 模板;无公开专条平台使用通用模板并标注"无平台背书")。
- **evidence**:创作者需求调研:58-63,:104(双轨发布、按目标平台参数化);市场综合分析:88(机会点排名第 4);商业模式调研:42,:77(抖音漫画号变现路径、条漫导出是现成钩子)。
- **effort**:低(导出服务预设常量 + 前端预设选择器 + 模板复用;无 schema 变更)。
- **priority**:P1
- **risk**:各平台官方像素规格本轮调研未取得权威来源(需求:61 标注为传闻口径),预设值必须标注来源与可配置性,不能把传闻数字写成硬校验。

### P2-1 中文文字原位编辑通道(Qwen 系接入作为文字检查修复备选)

- **problem**:图中文字是 ★★★ 中频痛点;主流实践"AI 不画字、后期叠加"与产品现状一致,但 Qwen-Image-Edit 的中英双语图中文字原位编辑已可用,对中文对白/拟声词修正是可争取的差异化。
- **what**:在 P0-1 能力位落地后,为"文字检查不通过"的修复路径增加图中文字原位编辑选项;接入 Qwen-Image-Edit(经 OPENAI 兼容协议或原生适配器);产出仍走候选 + 人工校对门槛,不绕过"文字采用唯一门槛是人工确认"。
- **evidence**:技术趋势调研:42-43,:108(Qwen 双语文字编辑直接可用);创作者需求调研:44-48(文字痛点、叠加为主流);市场综合分析:35(信号 8:可争取的差异化,默认仍后置叠加)。
- **effort**:高(新适配器/能力声明 + 真实供应商集成 + 质检链路联动)。
- **priority**:P2
- **risk**:依赖 P0-1 与真实供应商验收(延迟清单);若叠加排版已满足用户,原位编辑可能低频——先观察接入成本再放量。

### P2-2 动态漫画导出(已采用页 → 图生视频片段)

- **problem**:图生视频+原生音轨 API 化已完成,竞品(Dashtoon→Frameo、ComicAI→SkyReels、Toona)正涌入动态漫画位;但按秒计费与 Sora 停服先例要求后置且必须平权接入。
- **what**:"已采用页面 → 动态片段"导出管线,平权接入视频供应商(Veo 3.1 / Wan2.2 开源可自托管兜底);**先确认账本计量模型**——当前 `unit_kind` 检查约束仅含 TEXT_TOKENS/IMAGES/MIXED/UNKNOWN(apps/api/app/models.py:717-718),无时长维度,接入视频供应商前需先扩展计量单位(秒),具体扩展方式以账本契约为准;导出层沿用 fail-closed 能力声明。
- **evidence**:技术趋势调研:48-56(API 化完成、$0.05–0.60/秒);市场综合分析:89(机会点排名第 5,要求供应商平权);竞品调研:123(相邻生态位竞品涌入,需定位集成 vs 自建)。
- **effort**:高(新供应商类型 + Worker 任务 + 账本计量单位扩展)。
- **priority**:P2
- **risk**:单次导出成本敏感度远高于静态页;Sora 停服证明视频供应商生命周期风险高,接入即须可替换;排在静态链路稳固与账本秒计费之后。

### P2-3 批量升清派发(在已交付的单页升清之上补批量选择)

- **problem**:单页升清已交付——`POST /candidates/{id}/upscale` 支持 2K/4K、升清结果经 `attach_derived_lineage` 走派生候选不覆盖原图(apps/api/app/api/routes/workflow/inspection.py:307-399;`UpscaleRequest` 限定 2K/4K,apps/api/app/schemas.py:1280-1288)。PRD 的剩余缺口仅是"批量选择页面升清"(plan.md:1279,14.4 节);4K/放大能力集中在闭源旗舰与 Toona 类后处理工具,用户缺少对已采用页的批量成品升清路径。
- **what**:对已采用页面提供**批量选择派发**——逐页复用现有单页升清路由/任务/派生链,不新建升清通道;能力位按 P0-1 的分辨率档位声明路由;账本按档位计价。
- **evidence**:plan.md:1278-1286(14.4 节支持列表中"批量选择页面升清"为唯一未落地项);技术趋势调研:9-10(4K 集中闭源旗舰、档位定价);竞品调研:85(Toona 类占后处理生态位,可作集成对象参照)。
- **effort**:中(复用现有单页升清路由与候选派生链,主要是批量选择 UI + 逐页派发编排 + 批量失败聚合;依赖 P0-1 档位维度)。
- **priority**:P2
- **risk**:升清质量差异大且真实效果需供应商实测;与外部放大工具(Toona 免费 beta)存在零成本替代,优先级让位于链路内差异化项。

## 依赖关系与排序理由

- **P0-1(能力位)是几乎所有后续项的前置**:P1-2 槽位映射、P1-1 分层计价、P2-1 文字编辑、P2-3 升清全部消费它。
- **P0-2(生命周期)独立于其他项但时效最强**:Gemini 2.5 Flash Image 已于本调研前三天停服(2026-10-02),每拖一个迭代就多一批"目录里躺着死模型"的用户。
- **P0-3(留痕包)是最便宜的最大差异化**:数据全部已在库中,做的是聚合与叙事,但需先补五类检查完整性闭环(README.zh-CN.md:136);它也是 P1-3 投稿包的模板来源。
