## MangaFlow 0.2.0 产品扩展 TodoList（2026-08-30）

### 版本结论

- [x] **将本轮规划定义为 `0.2.0` 里程碑。** 当前根包、Web 与 API 仍是 `0.1.0`，代表已经实现的 MVP 基线；本轮包含供应商中心地位调整、一级资产扩展、视觉编辑器、自然语言导演和桌面壳，属于明显的新功能版本，而不是 `0.1.x` 修补版。
- [ ] **在 `0.2.0` 达到发布门槛时统一修改三个 manifest 的版本号并补充变更记录。** 规划阶段只声明目标版本，不提前把未完成能力标成已发布。`plan.md` 保留 V1.0 原始 PRD 作为历史输入，新需求和实际优先级以本节为准。

### 排序原则与依赖

本轮不沿用用户输入顺序。先统一模型/供应商和可观测性底座，再补一级资产与编辑数据契约，随后建设视觉分镜和导演能力，最后完成全局文案、动效、性能与桌面封装。UI 文案精炼是贯穿每个功能 PR 的验收项，并在末尾做一次全局收口。

```text
供应商平权与统一调用契约 ─┬─> CLI 生图通道
                           ├─> 用量与成本账本/看板
                           └─> 自然语言导演与局部重绘

场景资产 + 角色模型包 ───────> 视觉分镜编辑器 ──> 自然语言导演与局部重绘

核心工作流稳定 ─────────────> 全局 UX 收口 ─────> 桌面端封装与发布
```

### M4：自然语言导演与局部重抽卡

- [ ] **V02-40（L3，组长设计、GLM 实现优先）：建立自然语言导演命令层。** 用户可用自然语言修改页面、格子、角色姿态/表情、镜头、场景、时间天气、气泡和文字位置。模型只生成受 schema 约束的编辑命令，服务端校验目标、版本和资产引用；执行前展示结构化 diff，可逐条接受/拒绝，并支持撤销。禁止让模型直接任意修改数据库或文件。
- [ ] **V02-41（L2，Grok UI 优先）：设计导演工作区。** 以“画布 + 选区 + 对话/命令历史 + 变更预览”为核心，点击页面/格子/气泡即可建立明确上下文；短命令可直接预览，歧义命令要求确认目标。界面不堆叠解释性废话，错误信息给出可执行的下一步。
- [ ] **V02-42（L3 后端）：实现局部重抽卡候选链。** 可对单格、选区、气泡周边或指定元素创建局部编辑任务，保存 mask、父候选、编辑命令、参考资产和模型参数；结果作为新候选/派生候选，不覆盖原图，不自动替换当前采用版本，也不触发整页重生。
- [ ] **V02-43（L2，Grok UI/浏览器优先）：实现局部选区与结果比较。** 支持点击图片进入局部修改、画笔/框选 mask、羽化与撤销、原图/结果对比、同一区域多次抽卡、收藏和采用；采用后只使受影响的检查与后续连续性进入待复核，避免无关页面整批失效。
- [ ] **V02-44（L3 验收）：验证供应商能力差异和失败恢复。** 对支持原生 mask、仅支持 image edit、只支持整图生成的模型分别定义可用行为；不支持局部编辑时明确提示或由用户确认降级方案，禁止静默整页重生。覆盖取消、超时、旧 Worker 晚返回、素材租约和费用重复计量。

### 派工与合并规则

- L1 可交给 Antigravity/Gemini 做小而明确的实现或文档；L2 UI、浏览器与性能优先交给 Grok；跨模块重构和限定范围的 L3 实现优先交给 GLM。L3 的设计、迁移、进程/安全边界和最终验收由组长独立负责或复审。
- 每个编号默认是一个 Issue 边界；`V02-14A/B/C` 必须分别派工。实现、真实外部环境验收、无关重构不得塞入同一 PR。
- 每个行为变更必须带回归测试；涉及 schema 时同步 `docs/data-model.md`，涉及模块/进程边界时同步 `docs/architecture.md`，涉及供应商时同步 `docs/provider-platform.md`。
- 不因测试全绿、代理总结或 PR 已打开就视为完成；合并前审阅精确 SHA/diff，并按风险独立运行门禁。真实供应商、CLI、PostgreSQL、Redis/RQ 或桌面安装环境缺失时如实记录边界。

### P1-1 修复任务幂等插入竞态 ✅ 2026-08-27 完成
