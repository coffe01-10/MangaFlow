## 验收结果

- [x] Nano Banana 2 与 Nano Banana Pro 在 UI/API 中平级，每个候选显式选择模型。
- [x] 角色使用主要姓名、绰号和参考图；绰号冲突会标记人工确认。
- [x] 原文按来源区间无损分段；覆盖率不足时拒绝生成候选。
- [x] 动态分页不设总页数上限，单页硬上限 180 字、最多 8 个气泡。
- [x] 每次请求只创建一个页面候选，不自动生成后续页。
- [x] 同页可建立多个批次与候选，可收藏多个、采用一个。
- [x] 下一页连续性只引用当前采用版本；换选后标记后续页待复查。
- [x] 素材库按章节、页面、批次组织，并可容纳角色、服装、风格和修复素材。
- [x] 假模型/禁用队列测试覆盖 8 路任务隔离、取消、重试与幂等。
- [x] 17 项后端测试、Ruff、ESLint、Next.js 构建、Alembic 升级/回滚全部通过。
- [x] Codex 内置浏览器实测 2127 字章节生成 14 页、全部显示原文覆盖完整；单次抽卡创建 1 个 Pro 候选并可收藏到批次素材库。
- [x] 真实 Vertex 低 token 文本调用成功；Nano Banana 2 返回一张 1K 图片，验证后未落盘。

## 运行边界

- 页面图片仍必须由用户逐页主动生成，没有无人值守整章生成入口。
- Redis/RQ 是实际 Worker 路径；未启动 Redis 时任务持久化为 `WAITING`，不会静默回退为同步付费调用。
- 浏览器验收使用 `QUEUE_ENABLED=false`，因此 UI 抽卡没有执行付费生图；另以独立烟雾测试完成了计划限定的一次低 token 文本调用和一次 1K 图片调用。
- 复杂图层、多用户协作和移动端不在 MVP 范围。
