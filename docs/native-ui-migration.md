## 原生框架与实现边界

- `ProjectPages` 集中保存九个项目一级页面的顺序、名称、描述与实现状态；
  与 Web `navigationItems` 及项目工作流/设置入口一致。
- `ProjectNavigation` 负责当前页与去重通知。顶部项目面包屑、侧栏选中状态、
  `WorkspacePageFrame` 页面标题共享同一份状态；项目切换继续保留当前页面类别。
- `WorkspacePageFrame` 是原生 ContentControl，主题统一定义标题、描述、状态与正文插槽。
  现有原作/任务正文保持实例与数据绑定，页面切换只改变可见性。后续独立业务 View
  替换 `MigrationPage`，不在 MainWindow 继续堆叠完整业务逻辑。
- `MigrationPage` 只是明确标记的功能清单。没有模拟数据、假保存/生成按钮或无限加载状态；
  不把框架完成算成业务 UI 完成。资产子导航、画布工具栏、检查器等仍需后续独立视图。
- 读取资源显式登记，目前只有 `chapters` 与 `jobs`。切换先取消原有读取、同步更新界面，
  即使断网也可导航。未接通页面和其 F5 不发请求、不显示“刷新成功”。
- 保留现有异步 API、取消令牌、非激活窗口停止轮询、原生宿主与进程树所有权。
  本轮为 L2 UI 切片，由 lead 直接实现；没有后台生命周期、schema、凭据或付费接口改动。

## 分阶段交付与验收

当前状态：NUI-0 盘点和 NUI-1 框架完成，其余阶段待实现。下一最高优先级为
**NUI-2A 完整原生项目设置**（独立 View/状态模型；五分区、模型目录、版本冲突保留
草稿、重复保存去重、切项目隔离、名称确认后软删除并回首页；不修改 API/schema）。
然后依次执行 NUI-2B 原作/任务/首页补齐、NUI-2C 供应商/全局设置，再进入 NUI-3。
每次只取一个可独立验收的切片。

2026-09-07 用户明确授权后，计划、完成状态、验证结果及下一优先级已同步到
[roadmap](roadmap.md) 顶部的 WPF 原生客户端队列；此前文档写入审批阻塞已解除。

1. **NUI-1：导航和页面容器。** 九个入口、即时选中态、项目上下文、可折叠侧栏、
   共享标题/正文、明确待迁移状态；断网/重复选择/迟到响应回归。当前完成。
2. **NUI-2：把已有原生业务补齐。** 先项目设置，再原作修订/删除/撤回、任务详情，
   再全局供应商与运行/诊断设置、首页创建参数。每片先逐字段对照 Web 和 API schema，
   覆盖 loading/empty/error/dirty/saving/conflict/success；409 保留草稿，切换项目不串数据，
   写入中重复点击只发一次。真实供应商验证与付费冒烟另行验收。
3. **NUI-3：资产与剧本。** 先只读列表与五类子导航，再档案编辑/上传，再包版本/引用与
   场景/剧本编辑；沿用同一接口和版本语义。缩略图分页，原图按需加载并取消离开后的请求。
4. **NUI-4：两种画布。** 分镜联系表/画布/检查器与工作流 DAG 分开实现；统一坐标、缩放、
   键盘、选择、撤销、草稿冲突和离开确认。宽屏停靠，窄窗口抽屉；验收先离线再真实 API。
5. **NUI-5：生成与导演闭环。** 先只读候选/素材库/大图，再生成/采用/质检/导出，最后导演
   与局部编辑。生产门禁、付费确认、失败恢复、血缘与撤销完全沿用服务端契约。
6. **NUI-6：全局完整性。** 用量看板、帮助全文、任务成本详情、全局任务底栏、快捷键、
   焦点恢复、空/错/等待状态与所有弹窗对照；17 页和内嵌工作区全部逐项验收。
7. **NUI-7：流畅性与发布。** 940/1280/1440 DIP 与 100/125/150/200% DPI 对照；采集启动
   首帧、导航响应、长列表内存与双画布拖拽帧时间，保留全部样本（包括失败）；固定数据集和
   硬件后设立预算，不以主观“像 Codex”宣称达标。受支持 .NET LTS、安装/升级、签名及
   退出/崩溃清树独立发布验收。不得用离屏渲染替代窗口实机或性能数据。
